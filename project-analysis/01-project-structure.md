# هيكلية المشروع وتوزيع المجلدات (Project Structure & Folders Map)
## Attendance Recording System

---

### 1. خريطة المجلدات الجذرية للمشروع (Root Directory Map)

تم تصميم المشروع بنمط **Monorepo** متعدد الحزم يُدار بواسطة أداة الحزم `pnpm` وملف التهيئة `pnpm-workspace.yaml`.

```
Attendance recording system/
├── .github/                       # إعدادات وسير عمل GitHub Actions المؤتمتة
│   └── workflows/
│       └── ci.yml                 # مسار البناء والفحص والتحقق المؤتمت (CI Pipeline)
├── apps/                          # التطبيقات والخدمات البرمجية الرئيسية
│   ├── api/                       # خادم الواجهات الخلفية وقواعد البيانات (NestJS + Prisma)
│   └── web/                       # تطبيق الواجهة الأمامية وتجربة المستخدم (Next.js 14 App Router)
├── backups/                       # مجلد حفظ نسخ قواعد البيانات الاحتياطية الرسمية
├── docs/                          # وثائق المراحل الهندسية وتقارير الترحيل والأمان السابقة
├── postgresql/                    # محرك PostgreSQL محلي مستقل مدمج للتطوير
├── scripts/                       # نصوص مساعدة لإدارة النسخ الاحتياطي في نظام Windows
├── .env                           # المتغيرات البيئية العامة المشتركة
├── .gitignore                     # الملفات والمجلدات المستثناة من التتبع في Git
├── .npmrc                         # إعدادات pnpm وعزل التبعيات (node-linker, hoisted)
├── package.json                   # الحزمة الجذرية وتعريف أوامر التشغيل الموحدة
├── pnpm-lock.yaml                 # شجرة قفل التبعيات الصارمة لبيئة العمل
└── pnpm-workspace.yaml            # تعريف مجلدات التطبيقات المندرجة تحت المنظومة
```

### 2. التحليل التفصيلي لكل مجلد في المشروع

#### 2.1 مجلد `apps/api/` (الواجهة الخلفية والخادم)
- **الوظيفة الأساسية**: يمثل قلب النظام البرمجي وعقله المدبر. خادم مبني على إطار عمل NestJS بلغة TypeScript مسؤول عن توفير واجهات برمجة التطبيقات (REST APIs)، وقنوات الاتصال الحي (WebSocket عبر Socket.IO)، والاتصال بقاعدة البيانات عبر Prisma ORM، وتطبيق كافة قواعد التحقق الأمني والصلاحيات وإدارة الجلسات.
- **لماذا يوجد؟**: لعزل منطق الأعمال وقواعد البيانات تماماً عن واجهة المستخدم، وتوفير خادم مستقل يمكن تشغيله واستضافته كخدمة ويب دائمة (على سبيل المثال على Railway أو Render).
- **محتويات المجلد**:
  - `prisma/`: ملفات النمذجة `schema.prisma` وجميع ملفات الترحيل التاريخية `migrations/`.
  - `scripts/`: نصوص برمجية خاصة بإنشاء الكادر الأولي (`initial-setup.ts`, `create-staff.ts`, `seed-lecturers.ts`, `disable-owner.ts`).
  - `src/`: الكود المصدري مقسم بنمط Modular Architecture:
    - `common/`: الثوابت الأكاديمية (`academics.ts`, `roles.ts`, `coverage.ts`)، الحراس (`auth.guard.ts`, `permissions.guard.ts`)، المزخرفات (`decorators`)، والأدوات المشتركة (`utils`).
    - `modules/`: الوحدات الوظيفية المستقلة (13 وحدة: Auth, Lecture, Attendance, Student, Section, Course, Assignment, Followup, Timetable, Reports, Staff, Audit, Setup).
    - `prisma/`: خدمة الاتصال والتكامل مع قاعدة البيانات `PrismaService`.
  - `test/`: أجنحة الاختبارات المؤتمتة الصارمة (`security.test.ts`, `staff-management.test.ts`, `phase2.test.ts`, `reports.test.ts`).
- **الارتباط بالمشروع**: يخدم الواجهة الأمامية `apps/web` عبر HTTP REST و WebSocket، ويتصل بقاعدة البيانات عبر متغير `DATABASE_URL`.

#### 2.2 مجلد `apps/web/` (الواجهة الأمامية وتجربة المستخدم)
- **الوظيفة الأساسية**: تطبيق واجهة مستخدم حديثة وتفاعلية مبني على إطار Next.js 14 باستخدام نظام التوجيه الحديث (App Router). يتيح للكادر التدريسي والإداري إدارة المحاضرات، مسح رموز QR عبر كاميرا الجهاز مباشرة، استعراض نسب الحضور والغياب، وإصدار التقارير.
- **لماذا يوجد؟**: لتوفير تجربة مستخدم سريعة وخفيفة وتعمل مباشرة من أي متصفح ويب على الحواسيب والهواتف الذكية مع دعم كامل للغة العربية (RTL) والتصميم المتجاوب (Responsive).
- **محتويات المجلد**:
  - `src/app/`: المسارات والصفحات (المحاضرات `/`، تسجيل الدخول `/login`، الطلاب `/students`، الأكاديميات `/academics`، المتابعة `/followup`، التقارير `/reports`، الكادر `/staff`).
  - `src/components/`: المكونات القابلة لإعادة الاستخدام:
    - `camera/`: قارئ بطاقات الـ QR عبر الكاميرا `CameraScanner.tsx`.
    - `reports/`: ألواح ومكونات الرسوم البيانية وفلاتر التقارير.
    - `modals/`: النوافذ المنبثقة التفاعلية (إدارة الشعب، تصفير الغياب، طباعة PDF، كروت الطلاب).
    - `layout/`: شريط التنقل العلوي `Navbar.tsx`.
    - `auth/`: حارس الواجهة لحماية الصفحات `RequireAuth.tsx`.
  - `src/lib/`: المكتبات والعملاء المساعدين:
    - `api.ts`: عميل HTTP الموحد للتواصل مع الخادم وإرسال كوكيز الجلسة.
    - `auth.tsx`: مزود سياق المصادقة (AuthContext) وحفظ حالة المستخدم المسجل.
    - `camera-errors.js`: مترجم أخطاء الكاميرا إلى رسائل عربية واضحة ومفهومة.
  - `test/`: اختبارات معالجة أخطاء الكاميرا المستقلة.
- **الارتباط بالمشروع**: يستهلك واجهات الـ Backend عبر المسارات النسبية `/api/*` وعبر إعادة التوجيه (Rewrites) أو عناوين البيئة السحابية.

#### 2.3 مجلد `backups/` (النسخ الاحتياطية)
- **الوظيفة الأساسية**: مجلد مستودع مخصص للاحتفاظ بالنسخ الاحتياطية لقواعد البيانات بصيغتي Dump الثنائية (`.dump`) ونصوص SQL الخام (`.sql`).
- **لماذا يوجد؟**: لضمان عدم ضياع أي بيانات حقيقية عند تنفيذ الترحيلات أو الصيانة، ولتوفير إمكانية الرجوع الفوري لأي نقطة زمنية سابقة (Point-in-time Recovery).
- **المحتويات الملحوظة**:
  - `prod-railway-20261110-095812.dump` و `.sql`: أحدث نسخة مأخوذة من قاعدة بيانات الإنتاج الحقيقية المستضافة على منصة Railway (تاريخ 10 نوفمبر 2026) بحجم يقارب 4.5 ميجابايت وتضم 297 طالباً و11 شعبة.
- **الارتباط بالمشروع**: تستخدمه نصوص الاستعادة والفحص مثل `scripts/backup/restore-postgres-test.ps1`.

#### 2.4 مجلد `docs/` (التوثيق المرجعي للمشروع)
- **الوظيفة الأساسية**: يضم سجل القرارات المعمارية والتقارير الفنية المنجزة في كل مرحلة من مراحل تطوير النظام.
- **لماذا يوجد؟**: لتأريخ التغييرات، وتوثيق أسباب الاختيارات التقنية، ومراجعة معايير الأمان والتوافقية عبر دورة حياة النظام.
- **أهم الملفات بداخله**:
  - `PHASE1_REPORT.md` و `PHASE1_FINAL_FIXES_REPORT.md`: توثيق الأساس الأولي ونظام الجلسات والأمان.
  - `STAFF_MANAGEMENT.md`: تفاصيل نظام الكادر، ومستويات الصلاحيات، وآلية تشفير كلمات المرور.
  - `POSTGRES_MIGRATION.md`: دليل الانتقال التقني من SQLite إلى PostgreSQL المحلي والسحابي.
  - `PHASE3_FINAL_REPORT.md`: التقرير الشامل للمرحلة الثالثة وميزات المحاضرات المتعددة والجدول الدراسي والحضور عبر الشعب.
  - `BACKUP_RESTORE.md`: دليل إجراءات النسخ الاحتياطي والاستعادة واستخدام أداة `pg_dump` و `pg_restore`.

#### 2.5 مجلد `scripts/` (نصوص الأتمتة والصيانة)
- **الوظيفة الأساسية**: يحتوي على نصوص برمجية مكتوبة بـ PowerShell مخصصة لأتمتة مهام إدارة خادم PostgreSQL والنسخ الاحتياطي الدوري على بيئات Windows.
- **أهم الملفات**:
  - `backup/backup-postgres.ps1`: نص أتمتة لأخذ نسخة احتياطية محلية بصيغة `custom dump` وحفظها في مجلد النسخ مع إزالة النسخ القديمة التي تتجاوز مدة معينة.
  - `backup/register-backup-task.ps1`: نص لتسجيل مهمة دورية مؤتمتة في Windows Task Scheduler لتشغيل النسخ الاحتياطي تلقائياً كل 6 ساعات.
  - `backup/restore-postgres-test.ps1`: نص لاختبار استعادة النسخ الاحتياطية في قاعدة بيانات اختبارية مؤقتة للتحقق من سلامتها وخلوها من التلف.

#### 2.6 مجلد `.github/` (سير العمل المؤتمت CI/CD)
- **الوظيفة الأساسية**: تهيئة خطوط الأتمتة السحابية عبر GitHub Actions.
- **الملف**: `workflows/ci.yml`.
  - يقوم بتشغيل بيئة Ubuntu متكاملة مع خدمة PostgreSQL 16.
  - ينفذ تثبيت الحزم عبر `pnpm install --frozen-lockfile`.
  - يولد عميل Prisma عبر `prisma generate`.
  - يطبق الترحيلات ويفحص بنية الواجهة الخلفية `pnpm --filter @attendance/api build`.
  - يجري الفحص النوعي للواجهة الأمامية `pnpm --filter @attendance/web typecheck`.
  - يشغل كامل أجنحة الاختبارات للتأكد من عدم وجود أي تراجع برمجي (Regression).

### 3. تصنيف المجلدات والملفات المولدة (Generated & External Directories)

خلال فحص المشروع تم رصد عدد من المجلدات الضخمة التي يتم توليدها آلياً بواسطة الأدوات ويجب تمييزها وعدم معاملتها ككود مصدري كتبه المطور:

1. **`node_modules/` و `apps/*/node_modules/`**:
   - مجلدات الحزم الخارجية والمكتبات المحملة عبر pnpm.
   - يتم التحكم بها عبر `package.json` و `pnpm-lock.yaml`.
   - غير خاضعة للتحليل اليدوي ومستثناة من مستودع Git.
2. **`apps/api/dist/`**:
   - ناتج تصريف وترجمة كود TypeScript للواجهة الخلفية عبر NestJS Compiler (`nest build`).
   - يحتوي على ملفات JavaScript الناتجة وخرائط الأسطر (`.js.map`).
   - ملفات تنفيذية مؤقتة يعاد بناؤها عند كل عملية بناء أو نشر.
3. **`apps/web/.next/`**:
   - مجلد تخزين الكاش وملفات الحزم المترجمة للواجهة الأمامية لـ Next.js.
   - يضم صفحات الويب المبنية بنمط Server Components وملفات الحزم للعميل (Client Bundles).
4. **`postgresql/` (المجلد المدمج محلياً)**:
   - يحتوي على حزمة محرك PostgreSQL كاملة مدمجة لنظام Windows (Binaries, Shared Libraries, Timezones).
   - تم تضمينها في مسار المشروع لتسهيل تشغيل قاعدة البيانات محلياً دون الحاجة لتثبيت محرك PostgreSQL على نظام التشغيل يدوياً.
   - مجلد ضخم جداً من حيث عدد الملفات ويُعامل كبيئة تشغيل خارجية جاهزة (Vendored Binaries).
